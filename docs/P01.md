## Method and reuse

Baseline-v1 retains E05's existing grounded one-sentence/citation/abstention
instruction. Constrained-v2 adds scope/units/qualifiers, conflict handling and
untrusted-context instruction handling. Both prompt files are committed under
prompts/ and were frozen before calls. The thirty committed cases contain ten
direct facts, ten qualifications, six unsupported questions, two conflicts and
two embedded-context instructions. Facts are invented development examples.

The same gpt-5.4-mini alias generated both variants with reasoning_effort=none,
max_completion_tokens=1024, no automatic retries. All 120 actual response records
identify gpt-5.4-mini-2026-03-17. The same-family custom JSON judge receives only
question, context and actual generated answer: no gold answer or variant label.
It is E05's existing judge, not RAGAS or independent human evaluation.

E04's gate code and policy are reused unchanged: aggregate mean floors are 0.92
faithfulness and 0.90 relevance, with critical per-case floors 0.50. For each
individual case, passing assess_rows([row], policy, 1) also applies the mean floors
to that single score; additional lexical checks require a numbered citation for
answerable cases and an abstention phrase for unsupported cases. These checks are
not citation entailment or a semantic proof. Overlapping categories are reported.

The candidate passes the aggregate E04 score gate; baseline fails its critical
per-case check at P01-24. Both fail the stricter all-individual-contracts condition
because of their shared scored failure. No deployment/release is authorised by
this experiment, and no gate threshold was relaxed after seeing results.

## Adapter defect and zero-call correction

The first report omitted question/context fields when invoking E04, incorrectly
marking every row structurally failed despite recorded live answers and scores.
It remains supplied as original-report.json and is NOT the prompt comparison's
valid pass/fail result. The fixed adapter includes those fields; a new positive
test ensures a well-formed high-score comparison can pass.

The corrected assessment uses only saved answers and judge scores, without new
generation or judging. It verifies unchanged case/prompt/policy identities and
case ordering, restores the exact originally supplied question/contexts, and
rehashes all untouched answer/score/timing/usage/attempt fields. Source/newline
checks accept only LF/CRLF checkout differences, not changed case text or policy.
The corrected report records the original report SHA-256, original generation
revision and separate reassessment revision/mode. It never overwrites the original.

Windows Python 3.11 and clean Linux Python 3.12 reassessments produced identical
case rows, raw-evidence hash and paired outcomes. Cost aggregates differ only at
floating-point round-off below USD 1e-15; the displayed monetary figures agree.
Use corrected-report.json as the comparison, with usage.json and original-report.json
for provenance. This is an offline reassessment of actual live outputs, not a fresh
live rerun under the correction revision. All 120 calls succeeded; unknown usage
and automatic retries were both zero.

```sh

python run_evals.py --mode mock --report artifacts/mock-report.md
python prompt_compare.py --reassess <saved-original-report.json> --output artifacts/reassessed.json
```

Linux final source passed all 57 offline tests with the no-network guard and
both CLI commands. The mock report remains a placeholder, not live quality proof.
Live reproduction uses Python 3.11 and a provider key supplied through the normal
process environment, not a committed .env:

```sh
python prompt_compare.py --output artifacts/P01-new-run/report.json
```

It is billable: at most 120 calls and USD 1 reserved upper allowance; existing
report/ledger paths are rejected. A failed call stays reserved and appears in

makes the CLI return nonzero. Numeric quality/null results are still published.

## Remaining limits

Small authored sample; no held-out or repeated-trial comparison; same-family judge
bias; lexical contract heuristics; one observed judge/refusal disagreement; fixed
retrieval contexts; no retrieval evaluation; no Claude Code workflow validation;
no commercial adoption or production scale. B01 remains deferred. Review the
recorded failures and cost trade-off before choosing a prompt for another workload.
