# E04: fail-closed gate calibration

This change preserves E01: the generated answer is scored, and the reference is
never substituted. Real-mode rows now carry their retrieved context, judge error
category and policy outcome. Missing/invalid scores, empty output/context, unknown
numeric/named citations and severe per-case failures block even when a mean looks
acceptable. Judge exceptions produce a failed report instead of a silent skip.
Non-finite scores are rejected and serialised as null, never JSON NaN.

`evals/gate-policy.json` records provisional mean floors 0.92/0.90 and per-case
floors 0.50/0.50. The mean floors are 0.02 below the minima in the authored
acceptable development fixtures. These are explicit engineering assumptions
tested against known failures, not empirically validated population thresholds.
The three-case live check is a separate check of this provisional policy. B01
remains deferred; do not use this as a claim of production calibration.

```powershell
python -m pip install -r requirements-offline.lock
python -m pytest -p offline_guard tests -q
python calibration_smoke.py --output artifacts/E04-offline.json
```

With CPython 3.11 and an explicitly supplied OPENAI_API_KEY, an optional paid run:

```powershell
python calibration_smoke.py --live --output artifacts/E04-live.json
```

That command makes at most six gpt-5.4-mini judge calls with 1,024 completion
tokens each and no automatic retries. The custom JSON rubric is intentionally
identified separately from RAGAS. It sees question, contexts and generated text,
never a reference answer. Usage, resolved model IDs, latency and dated USD price
assumptions are in E04-usage.json. Use a new output directory for another paid
run: an existing ledger is refused rather than overwritten. The allowance is
per run, not an account-level billing cap.

The paid check compares three authored correct outputs with three numeric or
negation regressions. Its agreement table compares the judge with these labels;
it is not independent legal review. Offline tests add missing-context, invented-
citation, empty/NaN/missing metrics and judge-error cases. Citation checks prove
identifier existence only, not entailment; a genuine identifier can still be
attached to an unsupported claim. The missing-context rule treats an evaluation
row without supporting inputs as invalid; a full no-answer/abstention policy is
separate work.

No fresh application deployment gate is established by E04. R01 must validate
candidate revision/configuration and freshness. Generated reports stay ignored
and belong in the handoff/CI artifacts; durable summary is in evidence/E04.md.
