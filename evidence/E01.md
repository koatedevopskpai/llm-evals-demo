## Live run 2 — the acceptance criterion

The application adapter was replaced with one that wrongly abstains for every
case (`"The provided context does not contain this information."`), while the
reference answers remained correct and available in the golden set. A real RAGAS
judge scored it:

```
LIVE EVALUATION FAILED: faithfulness 0.000 (bar 0.9), relevancy 0.000 (bar 0.85); 0 unanswerable case(s).
EXIT CODE: 1
```

This is the E01 requirement demonstrated end to end: **a deliberately wrong
generated answer is passed to the scorer unchanged and fails, even though the
reference answer is correct.** Before E01 the same run would have scored 1.000,
because the reference was the answer.

## What the evidence establishes

- The scored text is the generated answer, not the reference. Proven by unit
  test on the payload builder and by the live fail case above.
- A missing generated answer is refused rather than substituted.
- A real run measures an adapter and fails when the adapter is wrong.

## What it does not establish

- Anything about quality at scale: **three cases** per run.
- That the 0.90 / 0.85 thresholds are the right ones (E04).
- That CI gates quality: no live evaluation runs in CI (R01/O02).
- That the RAGAS judge is correct; it is a model, and no human-reviewed sample or
  disagreement check exists yet.

## Findings

1. **Python 3.14 is unsupported for the live path.** With 3.14.5 the run aborts
   inside `datasets`/`dill`:
   `TypeError: Pickler._batch_setitems() takes 2 positional arguments but 3 were given`.
   Resolved by running on 3.11.9.
2. **`ragas` 0.2.x is incompatible with an unbounded `langchain`.** `import
   ragas` fails with
   `ModuleNotFoundError: No module named 'langchain_community.chat_models.vertexai'`
   when langchain resolves to 1.x. Pinning `langchain>=0.3,<0.4` (and the
   community/openai packages) fixes it. `requirements.txt` still declares
   `langchain>=0.2.0` with no upper bound, so a fresh live install will hit this.
3. **The reference-answer substitution was confirmed in source** before the fix,
   at the line the review identified — `evaluator.py:60` on `main` at the time.
