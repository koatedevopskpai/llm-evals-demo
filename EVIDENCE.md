## What it is

A reference harness for scoring **generated** answers against a golden set, with a
calibrated, fail-closed quality gate. It exists because the first version scored
the *reference* answer, which meant a perfect result was guaranteed regardless of
what an application produced.

| | |
|---|---|
| Scope | **Public reference build.** A harness, not a deployed service |
| Author | Koate Kpai — https://github.com/koatedevopskpai |
| Entry points | `run_evals.py`, `evaluator.py`, `answer_generator.py` |

## My contribution

- The **application adapter** (`answer_generator.py`): builds a grounded prompt from
  retrieved contexts and produces the answer under test.
- The **scoring contract** (`evaluator.py`): separate `generated_answer` and
  `reference_answer` fields; a refusal (`MissingGeneratedAnswer`) when no generated
  answer exists; a single payload builder (`ragas_payload()`) that never contains
  the reference.
- The **gate** (`gate_policy.py`, `evals/gate-policy.json`): mean floors plus a
  per-case floor that cannot be diluted by a mean, and hard structural checks.
- The **defect discovery**: the reference-answer substitution, found by reading the
  code rather than trusting a green run.

## What real mode measures

Real mode measures the quality of answers **the application adapter produced**, for
the recorded sample, scored by a real judge. It reports
`live_quality_established: true` when answers were generated by a provider and
scored on the generated text — that does **not** mean the bar was met; `status`
carries pass or fail. Mock mode is a wiring check whose scores are placeholders.

## The strongest evidence

### 1. The substitution bug is fixed, proven live

The original code passed `case.reference_answer` to RAGAS as the answer
(`evaluator.py:60` before E01). Two live runs, three cases each, `gpt-5-nano`, real
RAGAS judge:

| Generation | Result | Faithfulness | Relevancy |
|---|---|---|---|
| correct answers | `live_pass`, exit 0 | **1.000** | **0.910** |
| deliberately wrong answers, correct references present | `live_fail`, exit 1 | **0.000** | **0.000** |

Before E01 the wrong run would have scored **1.000**. That is the whole point of
the project: a test that cannot fail is not evidence. Full record:
[`docs/E01.md`](docs/E01.md), [`evidence/E01.md`](evidence/E01.md).

### 2. The gate is calibrated and fails closed

[`evals/gate-policy.json`](evals/gate-policy.json) sets mean floors of 0.92 / 0.90
and a **per-case floor of 0.50 that a mean cannot dilute**, with the rationale
recorded in the file.

A live development run scored a baseline of 1.0 / 1.0 and a known regression of
**0.0 / 0.667**, with **zero author/judge disagreements** — 6 calls, under $0.001.
Six authored outputs (three correct, three wrong) were checked by a live custom
judge. Offline suite: **50 passed**.

### 3. Two configurations compared on the same cases

[`docs/E05.md`](docs/E05.md): both configurations passed the same three authored
questions; the nano model was cheaper to generate with, the mini model showed lower
observed latency. **Neither result establishes statistical superiority** — p95 at
n=3 is descriptive only, and custom JSON-rubric scores are not comparable with RAGAS
scores. Offline suite: **53 passed**.

## How to reproduce

**Offline, free, no key** — this is what CI runs:

```bash
python -m venv .venv && . .venv/bin/activate
pip install pytest==8.4.2
python -m pytest tests -q
python run_evals.py --mode mock --report mock-report.md
```

**Live, billable** — requires CPython **3.11** and a key:

```bash
pip install "ragas>=0.2,<0.3" "langchain>=0.3,<0.4" "langchain-community>=0.3,<0.4" \
            "langchain-openai>=0.2,<0.4" "datasets>=2,<4" "pandas>=2"
export OPENAI_API_KEY=...
python run_evals.py --mode real --max-cases 3 --model gpt-5-nano --report artifacts/live-report.md
```

Two environment facts worth knowing before you try:

- **Python 3.14 breaks the live path**: `datasets`/`dill` fails with
  `Pickler._batch_setitems() takes 2 positional arguments but 3 were given`.
- **`ragas` 0.2.x needs `langchain` 0.3.x.** An unbounded `langchain>=0.2` resolves
  to 1.x and `import ragas` fails.

Exit codes: `0` policy met, `1` policy failed (including empty or malformed results),
`2` refused before any provider call.

## One success trace, one failure

**Success.** A correct generated answer is scored on the generated text and passes;
the generated text is persisted in the report beside its scores, so the score is
auditable after the fact.

**Failure, blocked by design.** A case the application could not answer is scored
as a **failure**, not skipped — so a run that produced nothing cannot pass. The
mock path cannot satisfy a live-quality requirement, and a missing credential
refuses at exit code 2 before loading an SDK or issuing a request.

## What this does not establish

- **Quality at scale.** Live samples are **three cases**. The reports name their
  case count; do not generalise.
- **That thresholds are correct.** They are provisional and derived from the
  author's own fixtures — a weakness the policy file states itself.
- **That CI gates quality.** No live evaluation runs in CI. A green workflow means
  the offline checks passed, not that a deployment was quality-gated.
- **That the judge is right.** RAGAS's judge is itself a model. A human-reviewed
  sample and a disagreement check are not built.
- **Anything commercial.** No deployment integration, no production reliability, no
  customers.

## Known weaknesses

- Custom JSON-rubric scores and RAGAS scores are **not comparable**; do not put them
  in one table.
- The mock thresholds (0.90 / 0.85) and the real policy floors (0.92 / 0.90) differ
  on purpose, but a reader comparing them without reading `EVIDENCE_MODES.md` could
  mistake one for the other.
- The golden set is 30 authored cases; coverage of adversarial, numeric and
  conflicting-source inputs is thin.
