# llm-evals-demo — evaluation harness for generated answers

A small reference harness for loading golden cases, generating an answer per
case through an application adapter, and scoring **the generated answer** against
faithfulness and answer-relevancy thresholds.

Two modes, deliberately distinct:

- **mock** — deterministic placeholder scores. A software wiring check. It says
  nothing about the quality of any application's output.
- **real** — generates an answer for each case with an OpenAI-compatible model,
  scores that answer with RAGAS, and records the generated text next to the
  scores.

## Implemented scope

- `golden_set.py` loads 30 question/reference/context cases. The reference answer
  is ground truth and is **never** scored.
- `answer_generator.py` is the application adapter: it builds a grounded prompt
  from the retrieved contexts and produces the generated answer.
- `evaluator.py` refuses to score when a case has no generated answer, rather
  than substituting anything. Mock mode returns deterministic placeholders.
- `run_evals.py` checks mean faithfulness >= 0.90 and answer relevancy >= 0.85
  by default. These are configured demonstration thresholds, not validated
  acceptance criteria for a particular application.
- Tests cover the substitution bug directly: a wrong generated answer fails the
  gate while a correct reference answer is present.

## What real mode measures, and what it does not

Real mode measures the quality of answers **your application adapter produced**,
for the recorded sample, using a real judge. It reports `live_quality_established:
true` when that happened — which means "answers were generated by a provider and
scored on the generated text", not "the bar was met". `status` says pass or fail.

Remaining limitations, stated plainly:

- The sample is small. Reports name their case count; do not generalise from a
  handful of cases.
- The mock job in CI can pass without any live evaluation. A green workflow is
  not evidence that a deployment was quality-gated.
- One live run was executed on **CPython 3.11** (see `docs/E01.md`). The
  `datasets`/`dill` serialisation path is incompatible with Python 3.14, so real
  mode requires a supported interpreter; the project targets 3.11.
- `ragas` 0.2.x requires `langchain` 0.3.x. An unbounded `langchain>=0.2`
  resolves to 1.x and breaks `import ragas`. Pin the stack when running live.
- This repository does not establish a deployment integration, production
  reliability or commercial use.

## Offline quick start

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install pytest==8.4.2
.venv\Scripts\python golden_set.py
.venv\Scripts\python -m pytest tests -q
.venv\Scripts\python run_evals.py --mode mock --report mock-report.md
```

Installation needs a package source unless dependencies are cached. The listed
test/mock commands require no provider key or model download. Mock scores are
placeholders, regardless of how high they are.

## Live quick start

Requires CPython 3.11 and an `OPENAI_API_KEY`. Live runs cost money and are not
run in CI.

```bash
python -m venv .venv && . .venv/bin/activate     # Python 3.11
pip install "ragas>=0.2,<0.3" "langchain>=0.3,<0.4" "langchain-community>=0.3,<0.4" \
            "langchain-openai>=0.2,<0.4" "datasets>=2,<4" "pandas>=2"
export OPENAI_API_KEY=...                        # never commit this
python run_evals.py --mode real --max-cases 3 \
    --model gpt-5-nano --report artifacts/live-report.md
```

Exit codes: `0` bar met, `1` bar missed or a case produced no answer, `2` refused
before making any provider call (no credential, mock asked to satisfy a
live-quality requirement, no cases).

## Planned improvements

comparison across configurations (E05), and version the benchmark and provenance
